# Этап 2.2: локальный аудит ввода и контента

Команда `npm run security:test:stage-2-2` запускает только локальные проверки. Она не отправляет запросы в production и не использует секреты.

Покрытие:

- CSV formula injection и лимиты строк, колонок, ячеек и размера;
- лимиты PDF, извлечённого текста и размеров исходных изображений;
- magic bytes для OCR-изображений и STT-аудио;
- защита AI-помощника от недоверенного финансового контекста и опасного вывода;
- allowlist внешних Telegram/OCR URL и базового URL приглашения;
- статический поиск опасных DOM/JS sinks.

После запуска краткий обезличенный отчёт сохраняется в `artifacts/security-stage-2-2/<timestamp>/report.json`. Каталог исключён из Git. Полные пользовательские данные, вопросы AI, токены и содержимое импортируемых файлов в отчёт не попадают.

## Исправленные проблемы

- Все CSV-экспорты нейтрализуют формулы, включая значения с пробелами и префиксами `=`, `+`, `-`, `@`.
- CSV-импорт ограничен 2 МБ текста, 5000 строками данных, 64 колонками, 8192 символами в ячейке и 100 000 ячеек; незакрытые кавычки отклоняются.
- PDF ограничен 50 страницами, 50 000 текстовыми элементами и 2 МБ извлечённого текста. Исходные изображения ограничены по размерности и числу пикселей до декодирования в OCR canvas.
- OCR-клиент принимает только публичный HTTPS endpoint, сверяет MIME с magic bytes и ограничивает ответы сервера.
- STT сверяет расширение и MIME с magic bytes; ответы Groq, сегменты и слова ограничены, а внешние тексты ошибок не возвращаются пользователю.
- Финансовый контекст AI нормализуется и передаётся как недоверенные пользовательские данные, ответы с активным контентом/ссылками отклоняются, диапазон дат ограничен годом. В журнале хранится SHA-256 fingerprint вопроса вместо открытого текста.
- Telegram URL, имя бота и одноразовый token проходят allowlist-проверку; Telegram API response ограничен.
- `APP_BASE_URL` для приглашений разрешён только для production-origin приложения либо localhost при локальном запуске Edge Function.

## Остаточные ограничения

1. Проверка AI-вывода и статический scanner снижают риск, но не являются математическим доказательством отсутствия prompt injection или XSS. Внешний AI в beta должен оставаться выключенным без явного server flag.
2. PDF.js, OCR и браузерные декодеры остаются сложными зависимостями. Лимиты снижают риск отказа в обслуживании, но не заменяют своевременное обновление зависимостей.
3. Проверка публичного OCR hostname выполняется для owner-controlled конфигурации и не является DNS pinning. GLM-OCR и отдельный OCR gateway этим этапом не тестировались.
4. Антивирусная проверка загружаемых файлов не добавлена: бесплатного локального сервиса в текущей browser-only архитектуре нет, а файлы не сохраняются на сервере приложения.
5. Production не атакован и не изменён. Контролируемый production smoke нужен только после отдельного разрешения на релиз.

## Будущий production-релиз

После отдельного разрешения владельца:

1. Push локального коммита в `main`.
2. Production deploy Vercel.
3. Redeploy Edge Functions: `ai-assistant`, `invite-user`, `stt-transcribe`, `telegram-link`.
4. Ненагрузочный smoke: безопасный CSV/PDF импорт, приглашение, Telegram-link и ожидаемые отказы для поддельных MIME/опасных URL. AI/STT проверять только если их beta server flags включены.

Миграция базы данных для этапа 2.2 не требуется.
